**切换模式**：按 `V`，或点顶部「编辑 / 观察」按钮（`#btn-mode-edit` / `#btn-mode-view`）。

> ⚠ `Tab` **不是**切模式 —— 它是"切换智能放置候选点"（见 §7）。
> 旧的快捷键速查面板里那一行没跟着改，以本节为准（快捷键总表见 §13）。

**手机上**：

- 单指拖动 = 移动光标（**不动镜头**），单指轻点 = 放置/选择；
- 单指长按 = 瞄准 + 选中 + 拿起；
- 单指双击 = 取消当前放置；
- 双指开合 = 缩放，双指同向拖动 / 快速滑动 = 旋转镜头；
- 双指手势期间**自动暂停绘制**，避免一边平移一边误改地形；
- 左/右虚拟摇杆（平移 / 旋转镜头）**默认关闭**（两个 112px 的圆盘会压住近一半操作区），
  需要的时候在 `#sandbox-options` 那类开关里自己开。

## 3. 地形笔刷

### 3.1 选择形状（5 种）

按 `[` / `]` 循环，或点左侧面板「形状」里的按钮：

| 形状 | 覆盖范围 | 什么时候用 |
| --- | --- | --- |
| 球形（默认） | 三维球体 | 通用，堆山、挖坑 |
| 立方 | 正方体 | 做方正的建筑基座 |
| 圆柱 | 立起来的圆柱（高度 = 直径） | 造柱子、造井 |
| 平面 | **只影响命中点所在的那一层** | 精细平面编辑、压平一大片 |
| 单点 | 只影响一格 | 配合密度做"点绘" |

### 3.2 选择模式（12 种）

按 `1`~`9` `0` `-` `=` 切换，或点「模式」里的按钮。作用方式分"按列"与"按球"两类：

| 键 | 模式 | 作用方式 | 效果 |
| --- | --- | --- | --- |
| `1` | 抬升 | 按列 | 在每列地表上堆叠若干层 |
| `2` | 下沉 | 按列 | 削掉若干层 |
| `3` | 平滑 | 按列 | 高度朝 3×3 邻域平均靠拢 |
| `4` | 抹平 | 按列 | 压到笔刷中心列的高度 |
| `5` | 材质刷 | 按球 | **只换材质不改形状** |
| `6` | 挖洞 | 按球 | 挖掉实心方块，**保留水** |
| `7` | 擦除 | 按球 | 什么都清掉，**连水一起** |
| `8` | 填水 | 按球 | 空气填成满格水 |
| `9` | 噪声刷 | 按球 | 按三维噪声随机补/挖，做粗糙岩面 |
| `0` | 随机刷 | 按球 | 按密度随机散布材质 |
| `-` | 边缘软化 | 按球 | 形态学开闭：削掉孤立凸块、填上窄缝 |
| `=` | 顶点捕捉 | 按列 | 把地表吸附到 2 格整数台阶，快速做平台与阶梯 |

### 3.3 半径与强度（都支持小数）

- **`Alt` + 滚轮** = 调半径（0.5~16）；也可以在面板里拖滑杆。
- **`Ctrl` + 滚轮** = 调强度（0.1~1.0）。

强度是小数怎么做到精细？关键在 `stochasticRound`：强度 0.1、衰减满值时高度增量是 `0.1 × 6 = 0.6` 层 ——
那么这一笔会有 60% 概率加 1 层、40% 概率什么都不变。所以强度滑块真的能"一点点磨"，而不是最小动一整层。

### 3.4 衰减（4 种）与作用方向（4 种）

- **衰减**：线性 / 平滑 / 恒定 / 反相（`#brush-falloffs`）—— 决定"越靠近笔刷中心改动越大"还是"整个范围一样多"。
- **方向**：法线 / `+Y` / `-Y` / 相机（`#brush-directions`）—— 决定"抬升"沿哪个轴推。

### 3.5 撤销粒度

**一次拖动 = 一步撤销**：左键按下的瞬间开一个事务（`BrushSystem.beginStroke()`），
拖动过程中的所有改动合并进同一个变更集合，抬起时整体交给 `CommandManager`。
所以你可以放心地长按涂抹，`Ctrl+Z` 一次就全退回去。

### 3.6 具体怎么抹平一座山

1. 按 `1` 选地形工具，按 `]` 切到「球形」，按 `4` 选「抹平」。
2. 把光标移到山顶，按住 `Alt` 滚滚轮把半径调到覆盖整个山顶（状态条会显示"影响 N 格"）。
3. 把强度滑杆拖到 0.5 左右，按住左键在山顶来回涂 —— 地表会被压到笔刷中心那一列的高度。
4. 想立刻看到硬边效果，按 `` ` `` 打开「地形线框」，再 `Shift+B` 重建全部网格。

## 4. 材质与纹理

- 每种体素都有**独立的顶面 / 侧面 / 底面**图案，用 `DataTexture` **程序化生成**（不加载任何外部图片）。
- 共 **19 种体素**：空气、草方块、泥土、石头、沙子、水、木头、砖块、钢材、玻璃、雪、冰、树叶、仙人掌、泥巴、圆石、大理石、玄武岩、岩浆。
- 共 **17 种图案**：纯色、颗粒噪点、斑点、细点、砖缝、横板木纹、竖纹、草顶、草沿、玻璃网格、水波、冰晶、金属拉丝、叶簇、仙人掌棱、熔岩裂纹、大理石纹。
- **顶点级 AO** 是烘焙进顶点色的，所以堆叠的方块之间会出现自然暗角；贴图四周压了一圈暗边，相邻方块之间就有清晰分界。
- 要看每种体素的代表色：在「📊 性能与调试」面板最下面展开 **颜色图例** `#color-legend`。

### 5.1 面板布局（`#building-panel`）

### 5.2 找东西

1. **搜索**（`#catalog-search`）：输入 `石墙` / `桌` / `船` / `杯子`。
   - 支持**空格分词**，多个关键词必须**全部**命中：`木 门` 会同时匹配名字、id、分类、二级分类、标签、说明。
   - 支持标签搜索，例如搜 `自然` 能找到树与巨石。
2. **分类标签页**（`#catalog-tabs`）：**11 个一级分类 + 全部 + 收藏**。
   顺序是刻意的（从"搭房子最常用的结构件"到"玩票性质的奇幻物件"）：
   🧱 结构 / 🚪 门窗 / 🪑 家具 / 💡 电器 / 🚿 厨卫 / 🖼️ 装饰 / 🚗 交通 / ⚙️ 机械 / ✨ 奇幻 / 🧸 小物品 / 🪴 植物。
3. **二级分类**（`#catalog-subs`）：切到某个一级分类后才出现（例如「结构 → 楼梯」）。在「全部 / 收藏」两个虚拟分类下不显示。
4. **排序**（展开「筛选与排序」）：默认 / 名称 / 质量 / 尺寸。
5. **只看收藏**：勾上 `#catalog-fav-only`。点物品卡片上的收藏标记即可收藏。
6. **最近使用**（`#catalog-recent`）：搜索框下面那一行，最多 12 个，**重复放同一个东西只要一次点击**；空的时候整行隐藏。
7. **长列表而不是分页**：滚到列表底部会自动追加 24 个（`IntersectionObserver`，观察的是物品网格这个真正的滚动容器）。
   没有观察器时退化成「显示更多」按钮。**DOM 是一批一批建的**，所以滚 394 个卡片不会一次性卡死。
8. **数量提示**（`#catalog-count`）会写全："共 394 个物品｜当前筛选出 N 个，已显示 M 个｜已选中「X」→ 到场景里点地面放置"。

### 5.4 内容包

展开「内容包」折叠块（`#catalog-packs`）：按一级分类分组，**关掉一个包只会把它从面板里藏起来，
世界里的东西不会消失**（面板上有这句小字）。两个入口（物品面板内联开关 + 设置区面板）读同一个存储键，任一边变化都会刷新另一边。

### 5.5 自定义物品

在「🧸 自定义物品」面板里可以用基本几何体拼一个东西。硬性约束（会给出中文原因）：

1. id 必须以 `custom_` 开头（否则自建物品会混进内置 id 空间，以后内置加同名物品会静默覆盖）；
2. `size` 必须等于 `parts` 的包围盒（否则碰撞体与视觉错位）；
3. 最低点必须正好是 0（原点在底面中心，这是全项目的约定）。

**不能**上传模型、不能自定义碰撞体形状、不能加新的物理组件类型 —— 纯前端没有模型解析器与付费存储。
删除自定义物品**不会**把世界里已经放好的那些删掉（面板上写明了，否则你会不敢删）。

### 5.6 放置设置

- **网格吸附**（`#build-snap`）与吸附步长（`#build-snapstep`：0.5 / 1 / 2 / 4 米）
- **自动贴地**（`#build-ground`）：把 `position.y` 设成地表高度（原点在底面中心，所以这就是全部）
- **旋转步长**（`#build-rotstep`：90° / 45° / 15° / 5°）
- 按钮组：`⟲ 旋转`（`Q`）/ `⟳ 旋转`（`E`）/ `🗑 删除`（`Delete`）/ `⧉ 复制`（`Ctrl+D`）/ `🎯 对准`（`F`）

## 6. 建造：从挑物品到放下去

1. 按 `2`（或点工具栏 🏠 建筑）切到建筑工具。右侧「建筑模型库」与「智能放置」「堆叠」三个面板会同时出现。
2. 在物品列表里点一个物品卡片。面板底部状态行变成"已选中「木墙」→ 到场景里点地面放置"。
3. 把鼠标移到地面上：会出现**幽灵预览**（绿 = 可放，红 = 不可放）与**脉冲高亮框**。
   高亮框 `depthTest = false`，所以**被山体挡住也看得见**。
4. 按 `Tab` / `Shift+Tab` 切换候选落点，或直接点「智能放置」面板里的候选列表 `#placement-candidates`。
5. 回车（或点「✓ 确认放置」）确认。放错了按 `Esc` 取消。

### 智能放置的 6 个候选来源

| 来源 | 说明 |
| --- | --- |
| 吸附点 | 模型自带的连接点（可 `G` 键开关「吸附点对齐」） |
| 堆叠 | 已有物体的顶面（见 §7） |
| 贴墙 | **门窗类物件会自动找最近的墙面贴上去** |
| 地面 | 地表高度 |
| 网格 | 按吸附步长对齐 |
| 空中 | 悬空位置（会按"放在空中会下坠"的开关决定是否变成会掉的动态刚体） |

打分 = 来源权重 + 稳定性 + 离光标距离 + 是否符合你当前朝向。每个候选都做了真检查：地形穿插（体素采样）+ 并列重叠（Rapier 形状重叠查询）+ 支撑（形状投射）。

### 落点看不见时怎么办

- 「✨ 智能放置」面板里四个开关：
  - **候选点跳远时镜头跟随（0.3 秒平滑）** `#placement-track-camera`：候选点**跳远超过 12 米**才介入，12 米以内不动镜头（每帧跟着光标晃的镜头会晕到没法用）；你一拖鼠标 / 滚轮就**立刻中断**。
  - **候选点在视野外时显示边缘箭头** `#placement-edge-arrow`：屏幕边缘给箭头 + 距离。
  - **脉冲高亮框（穿透地形可见）** `#placement-highlight`。
  - **放在空中会下坠** `#placement-physics`。
- 吸附开关：吸附点对齐 / 吸附到支撑面 / 贴墙对齐（`#snap-anchors` / `#snap-surface` / `#snap-wall`）。

## 7. 智能放置与堆叠

### 7.1 候选点切换（`Tab`）

`Tab` = 下一个候选，`Shift+Tab` = 上一个；`[` / `]` 在建筑工具下也能切换候选。
原来的 `Tab`（切编辑/观察模式）**已经挪到 `V`** —— 理由是候选切换是高频操作，高频操作才配得上 `Tab` 这个最顺手的键。

### 7.2 堆叠：每个物体都是独立实体

**不是"重合成一个"，是叠罗汉**：A 放在 B 顶面时 A 的底部 Y = B 的顶部 Y；下方有多个物体时**取最高支撑面**。
层数超过 20 层时面板会给提示（`#stk-warning`）。

### 7.3 支撑面是一块有面积的资源

「🧱 堆叠」面板给出的都是真实读数：

| 读数 | 含义 |
| --- | --- |
| 层数 `#stk-layer` | 这个物体叠在第几层 |
| 支撑物 `#stk-support` | 它压在谁身上 |
| 支撑面面积 `#stk-support-area` | 支撑物顶面的总面积 |
| 已占用 / 剩余可用 `#stk-used-area` / `#stk-free-area` | 顶面被占了多少、还能摆多少 |
| 接触比例 `#stk-contact` | 接触面积 / 底面积 |
| 稳定性 `#stk-stability` | 绿（稳）/ 黄（临界）/ 红（不稳） |
| 还能放 `#stk-remaining` | 按当前小网格还能放几个 |

**顶面被按 4×4 小网格划格**（`#stk-surface-grid`，可调 2~8）：每个空闲格子都是候选点，
所以**一张桌子上就能整齐摆一排**，而不是只能放一个。

### 7.4 三个方向 + 连续堆叠

- **堆叠方向**：`↑ Y 叠高`（默认，一层层往上）/ `→ X 排列` / `→ Z 排列`（排成一堵墙）。
- **连续堆叠**（`#stk-quick-stack`）：**按住 `Shift` 放置**时开启，放下一个后继续叠同一个模型。
  - 撤销粒度可选：「整轮合并成一步」（默认，一次 `Ctrl+Z` 退掉整轮）或「每放一个算一步」。
  - 点「停止连续堆叠」或按 `Esc` 退出。

### 7.5 失去支撑会真的掉下来

地形被挖掉后 **450 ms 内**重新判定，悬空的静态物体转成动态刚体自由落体（M3 起走局部倒塌逻辑：
从地基出发做连通性标记，只有跟地基断开的那一块才倒，并有 **600 毫秒宽限期**先提示"有 N 个物体失去支撑，马上会掉"）。

### 7.6 稳定性是"用来说明为什么"，不是真实力学

`contactRatio` 与 `centerMargin` 的阈值是人为定的经验值，目的是让你一眼看出哪个摆放不靠谱。
**真实的倾倒交给 Rapier 动态刚体去算**，两者分工明确。

### 7.7 支撑调试面板

「🔍 支撑调试」（`#support-debug-panel`，默认折叠）是给"为什么这个被判成不稳"用的：
选中一个物体后它列出支撑面面积 / 已占用 / 剩余 / 接触比例 / 稳定性 / 索引耗时，
以及**这个支撑面上已经放了哪些物体**（`#sd-slot-list`）。
两个可视化开关：`支撑面与占用格子`、`稳定性着色（绿/黄/红）`。

## 8. 选择、拿起与微调

### 8.1 选择

| 操作 | 效果 |
| --- | --- |
| 左键点击 | 选中（`#select-status` 会显示已选数量） |
| `Ctrl` + 左键 | 加选 / 取消 |
| 拖拽 | **框选**（屏幕矩形投影判交） |
| `Ctrl+A` / 点「全选」 | 全选 |
| 点「选同类」`#btn-select-similar` | 选中世界里所有同 id 的物体 |
| `Esc` / 点「清空」 | 清空选择 |
| `Delete` / `Backspace` | 删除选中 |
| `Ctrl+D` | 复制选中 |

选 500 个物体和选 1 个的 draw call 都是 **1 次**（高亮合并成一个 `LineSegments`）。

### 8.2 拿起与放下

- `空格` 或点「✋ 拿起单个」拿起光标下的一个物体；**「🏗 拿起整结构」会做连通性 BFS**（把相连的一整栋楼一起拿起，不需要你预先分组）。
- 拿起时按**光标位移**跟随 —— 不是"把物体中心对齐到光标"，否则抓住的瞬间会跳一下。
- 拿起中的物体是 **kinematic**（自己不受力、能推开别人），所以拖动时不会因为碰撞被弹飞。
- `空格` 或点「⤓ 放下」放下；放下时**整体校验**，不合法就**自动还原**（拖着沙发穿过墙松手时不会卡住，也不会把世界搞坏）。
- 点「↺ 还原原位」或按 `Esc` 把所有拿起的东西放回原位。

### 8.3 微调

| 操作 | 步长 |
| --- | --- |
| `←` `→` | 沿 X 平移（微调步长 `#nudge-step`：0.25 / 0.5 / 1 / 2 米） |
| `↑` `↓` | `↑` = +Y，`↓` = −Y（**按住 `Shift` = 沿 Z** 平移） |
| `,` / `.` | 绕 Y 轴旋转，步长 `#fine-rotstep`（5° / 15° / 45° / 90°） |
| 面板按钮 | 六轴平移按钮 + 六轴旋转按钮（旋转支持 X / Y / Z 三轴） |
| `Ctrl+Z` | 撤销微调 |

每次微调都是**一步独立的撤销记录**。

### 8.4 镜像复制

「⇋ 沿 X 镜像」`#btn-mirror-x` / 「⇅ 沿 Z 镜像」`#btn-mirror-z`（或 `Ctrl+M` = 沿 X 镜像）。

**这是真镜像**：位置取镜像、绕 Y 取反、**几何体本身也在局部轴上镜像并反转三角形绕序** ——
少做第三步的话，不对称的模型（书架、汽车）看起来就是错的。

### 8.5 分组 / 预制件 / 蓝图

- **分组**：`Ctrl+G` 成组 / `Ctrl+Shift+G` 解散 / 点「选中组」选中整组。可命名（`#group-name`）、可嵌套。
- **预制件**：`Ctrl+P` 或点「保存选中」。选中即存，并带一张**等轴测 SVG 缩略图**（不额外开 WebGL 上下文）。
  点「放置」把预制件放到光标处，点「删除」移除。
- **蓝图**：`Ctrl+B` 或点「⬇ 导出选中」导出成**纯 JSON**（带版本与包围盒），可以互相分享；
  点「⬆ 导入蓝图」选文件导入并放置。

### 8.6 操作历史面板

「🕘 操作历史」**最多保留 100 步**（`DEFAULT_HISTORY_LIMIT = 100`），列表只**渲染最近 60 条**
（更早的折叠成一行"…还有 N 条更早的操作"，全画出来手机上滚不动；面板刷新按 200ms 节流）。
**点任意一条直接回退/前进到那一步**。
每组操作带 `group` 名，所以一次"框选后微调 20 个物体"是**一条**记录而不是 20 条。

## 9. 物理

### 9.1 物理参数面板（`#physics-panel`）

- **重力预设**（5 档）：地球 / 月球 / 火星 / 木星 / 零重力。
- **重力**（竖直）滑杆 —— 实时生效，改完就能看到东西飘起来或砸下去。
- **世界配置**：时间步（默认 16.67 ms/步）、最大子步（4）、求解迭代（4）、休眠阈值（0.5）。
- **默认物理参数**：摩擦、弹性、线性阻尼、角阻尼、最大速度。
- **物理材质**：下拉选一个材质 → 点「应用材质到选中物体」。换材质会同时改碰撞体的
  `friction`/`restitution`/`density`、刚体的阻尼，**并唤醒刚体**（睡着的东西不会用新参数）。
- **性能读数**：刚体（动态/静态）、接触对、求解耗时、步进耗时、休眠率。

### 9.2 刚体三种模式

| 模式 | 行为 | 怎么进入 |
| --- | --- | --- |
| `static` 静态 | 稳稳摆着 | 默认（放在有支撑的位置） |
| `dynamic` 动态 | 会掉、会翻 | 放在空中 / 失去支撑 / 逻辑连线动作 `set-mode` |
| `kinematic` 运动学 | 被玩家拿着，能推开别人、自己不受力 | `空格` 拿起 |

### 9.3 关节编辑器（`#joint-editor`）

6 种关节都走 Rapier 原生求解器：**固定 / 旋转（铰链）/ 滑动 / 球窝 / 绳索 / 弹簧**。

操作步骤：

1. 进入「🖱 选择」工具，选中**两个**物体（点一个、`Ctrl+左键` 点第二个）。
2. 在「⚙ 关节编辑器」里选**类型**（`#je-type`）。
3. 填**轴**（三个数字输入框 `#je-axis-x/y/z`）—— 用数字而不是 X/Y/Z 按钮，
   因为吊桥的轴经常是斜的，三个按钮表达不了。
4. 需要限位就勾「启用限位」（`#je-limits-enabled`）并填 min / max。
   ⚠ **单位写在界面上**：旋转关节是**弧度**、滑动关节是**米**。输入 90 会得到 90 弧度（≈ 14 圈），不是 90 度。
5. 需要马达就勾「启用马达」（`#je-motor-enabled`），选模式：
   - `velocity` 速度驱动：一直以目标速度转/推（需要行程限位挡住它），适合轮子、传送带；
   - `position` 位置驱动：用弹簧-阻尼走到目标角度并**停在那里**，适合"门开到 90° 就停"、活塞伸到 0.5 米。
   然后点「启动」`#je-motor-go`。参数有目标速度/位置、刚度、阻尼、最大力、反向。
6. 点「创建关节」`#je-create`。`#je-list` 里会列出世界里所有关节，选中可以在 `#je-selection` 里看到详情。

**限位是可看见的**：打开「⚙️ 物理框架」面板的「关节连线」与「关节锚点」调试绘制后，
旋转关节会在锚点处绕轴画一段圆弧（8 段折线）表示能转到哪，滑动关节沿轴画一条 min→max 的线段。
没有限位的关节不画（画一条"无限的线"只会让画面糊掉）。

### 9.4 触发器与逻辑门（`#logic-editor`）

**触发器是 Rapier sensor**，不是盒查询轮询 —— 所以不会漏掉快速穿过的东西，而且只在状态变化时才产生事件。

**三种拖拽连线步骤**（勾上 `#le-drag-mode`「拖拽连线模式」）：

1. 在视口里**按住一个物体** → 拾取为源，画一条跟随光标的虚线。
2. 拖动 → 覆盖层颜色随"光标下有没有合法目标"变绿/变红，文案变成"松手连到「木门」"。
3. 松手 → 两端预填（`#le-endpoints`），你选**事件**（`#le-event`）与**动作**（`#le-action`）后点「建立连线」`#le-create`。

> 为什么松手后还要点一下？一条连线至少需要"监听什么事件"与"执行什么动作"，而拖拽只表达了"从谁到谁"。
> 硬要自动连就必须猜一个默认值，猜错的后果是你得到一个自己不想要的连线 —— 那比多点一下烦人得多。

**6 种逻辑门**（`#le-gate`）：

| 门 | 语义 | 关键参数 |
| --- | --- | --- |
| 直接 | 事件到 → 立刻执行 | — |
| 或 | 任一输入触发 | — |
| 与 | 窗口内凑齐 N 个输入才执行一次，触发后清空 | `required`（2）、`windowMs`（400） |
| **非** | 抑制源在窗口内**没有**活动才执行 | `inhibitSourceId`、`windowMs` |
| 延时 | 排队等 N 毫秒再执行（**排队不丢弃**，连按两次会执行两次） | `delayMs`（500） |
| 计时 | 持续活动时每 N 毫秒执行一次 | `intervalMs`（1000）、`windowMs` |

可以用 `#le-cooldown` 设冷却、`#le-probability` 设概率。
**非门不能用拖拽配置** —— 它需要"抑制源"这个第二参照物，拖拽只能表达两个端点。面板上写明了原因。
"等于没设门"的配置（没有抑制源的非门、延时 0、要求 1 个输入的与门、周期小于 50ms 的计时门）会被 `validate()` 当**错误**报出来。

**注意**：连线目前**不进存档**（见 §11.4）。

### 9.5 20 个成品组合（`#combo-panel`，按 `K`）

`src/data/combos.ts` 里有 **20 个已经接好关节的成品**（会开的门、会转的风车、投石机、摩天轮…），
共 **64 个零件 / 46 个关节**，覆盖 5 个分类。选一个点下去就能看到物理效果，不用调任何参数。

### 9.6 物理沙盘模式（`#sandbox-panel`）

一键把世界变成"物理演示场"，勾选项：

- **全部转成动态刚体（会掉下来）** `data-sandbox="forceDynamic"`
- **自动打开调试可视化** `data-sandbox="autoDebugDraw"`（默认开）
- **暂停水与沙模拟** `data-sandbox="pauseFluid"`（默认开）
- **放置不再需要支撑** `data-sandbox="freePlacement"`
- **显示引导提示** `data-sandbox="showHint"`（默认开）

`#sandbox-effects` 会逐条列出"开启后会做什么"，`#sandbox-status` 显示当前状态。

### 9.7 应力着色（`#stress-panel`）

⚠️ **这不是有限元分析**：

```
应力 ≈ 0.55 × (1 − 支撑充分度) + 0.30 × 承重比例 + 0.15 × 悬挑比例
```

它能回答"我这座桥看起来合理吗"，**不能**回答"这根梁 3.2 秒后会不会断"。

用法：勾「打开应力着色」→ 选配色（热力 蓝→黄→红 / 单色灰度）→ 拖「显示阈值」滑杆
（只给超过阈值的物体着色，因为**低应力必须是纯白**，否则整座建筑变成一片颜色反而看不出哪里危险）
→ `#sp-stats` 看分布、`#sp-worst` 看"最危险的物体"→ 点「只看最危险的一个」`#sp-focus-worst` 直接飞过去。

> 应力着色与稳定性着色**互斥**（共用 `instanceColor` 通道同一条通道），面板上写明了。

### 9.8 物理框架面板（`#physics-debug-panel`，`F2`）

按"出问题时该看哪一层"分成四层，每层都有可观测出口：

| 层 | 内容 | 出问题时的症状 |
| --- | --- | --- |
| 1 · 刚体 | 有哪些东西参与模拟、什么模式 | 东西不动 / 乱飞 |
| 2 · 关节 | 6 种关节 | 该连着却散开 |
| 3 · 触发器 | 总/启用 | 进去没反应 |
| 4 · 逻辑连线 | 总/启用/已触发 | 拉了没反应 |

**调试绘制**（全部合批进 1 个 `LineSegments` + 1 个 `Points`，只多 2 次 draw call）：

| 开关 | 画什么 | 它**不**准确的地方 |
| --- | --- | --- |
| 关节连线 / 关节锚点 | 关节两端与锚点 | — |
| 绳索松弛长度 | 绳索未拉紧时的自然长度 | — |
| 触发器盒子 | sensor 的包围盒 | — |
| 逻辑连线箭头 | 连线方向 | — |
| 碰撞盒 | 每个碰撞体 | — |
| 接触点 | 求解器真实在算的接触点 | **只画当前帧还在的接触**，分离瞬间就没了 |
| 接触法线箭头 | 方向（指向分离方向） | **长度不是牛顿数** —— 是按穿透深度与接触点数缩放的相对量。所以它叫"接触法线箭头"不叫"受力箭头" |
| 速度向量 | 方向与相对大小 | 为可读性缩放过（1 m/s = 0.25 米），不是 1:1 |
| 按休眠状态着色 | Rapier 的真实休眠状态 | 与稳定性/应力着色**共用通道**，会互相盖住 |
| 只画线框 | 省性能 | — |

按钮：清空关节 / 清空触发器 / 清空逻辑连线 / 打印物理诊断。

## 10. 时间控制与回溯

### 10.1 暂停与单步

`P` 暂停 / 播放；`N` 单步前进 1/60 秒（或点「⏭ 单步」）。**暂停时物理完全不推进**
（Rapier 的查询管线只在 `world.step()` 里更新，所以暂停期间的堆叠判定走的是纯 AABB 数学，一样准）。

### 10.2 倍速

`0.25×` / `0.5×` / `1×` / `2×` / `4×`（`#tp-scales`，或顶部工具栏的按钮）。

**倍速靠"每帧推进更多子步"实现，不改时间步** —— 改步长会出现"同样一堵墙，1 倍速不倒、4 倍速倒了"。
慢速档是观察碰撞过程最有用的档位：一颗球落地的那一帧在 1 倍速下根本看不清。

### 10.3 时间轴与回溯

- **时间轴** `#tp-timeline`（0~299 帧，共 300 帧缓冲）：拖动它直接跳到那一帧。
- `R` 回溯一帧、`Shift+R` 前进一帧（顶部的「⏪」按钮）。
- `#tp-state` 显示「● 实时」或「历史回放中」；点「回到实时」`#tp-live` 回到当前。
- **回溯记录的是位姿**（位置 + 四元数），300 帧 ≈ 7.7 MB。
  ⚠ **它不重算接触力**（接触点是求解器的中间量），所以回溯后物理读数要等再跑一步才准。
  写回时会**清零速度**，否则物体回到历史位置后会带着当前速度继续飞。

### 10.4 关键帧快照

点「存快照」`#tp-snapshot`（或顶部的「📸」）。快照与回溯是两条不同的路：
**快照是"重置"而不是"回退"** —— 恢复它走的是 Rapier 的 `restoreSnapshot`，返回一个全新的世界对象，
所以是"回到那一刻"，而历史位姿是连续的帧回放。快照列在 `#tp-snapshots` 里，点一个即可恢复。
「清空回溯缓冲」`#tp-clear-history` 清掉 300 帧历史。

### 10.5 其它与时间有关的快捷键

- `Shift+B` = 重建全部区块网格（低频维护动作，从 `R` 挪过来了）
- `Ctrl+Shift+R` = 重新生成地形

## 11. 流体、沙土、存档

### 11.1 流体（`#fluid-panel`，按 `4` 切到流体工具）

#### 5 种流体类型（`#fluid-types`）

| 类型 | 相对密度 | 物理密度（kg/m³） | 黏性系数 | 粒子上限 | 特点 |
| --- | --- | --- | --- | --- | --- |
| 💧 水 | 1 | 1000 | 0.02 | 20000 | 基准流体：会流平、会溅、会被地形挡住 |
| 🫒 油 | 0.9 | 900 | 0.09 | 12000 | 比水轻 → 同一体积浮力更小，所以会浮在水面上 |
| 🍯 蜂蜜 | 1.4 | 1400 | 0.42 | 6000 | 又稠又重，黏性最高 |
| 🌋 岩浆 | 2.6 | 2600 | 0.30 | 8000 | 最重，且重力缩放 **0.85**（比别的流体"沉得慢"），有独立的视觉与音效参数 |
| 🥛 牛奶 | 1.03 | 1030 | 0.05 | 12000 | 略重于水 |

（数字来自 `src/fluid/FluidPresets.ts` 的 `FLUID_PRESETS`。注意：配置里存的是**无量纲的相对密度**
`restDensity`（水 = 1），耦合时由 `ParticleFluidField` 乘 1000 换成 kg/m³ ——
所以"水 1 m³ 全浸 → 浮力 9810 N"验证的是后者。）

（最终上限取 `min(预设上限, 设备档位上限)`，桌面档位上限是高配 20000 / 中配 12000 / 低配 6000，**手机一律 3000**。）

⚠ **这些参数是视觉调参的结果，不是物理常数**：水的真实动力黏度是 1 mPa·s、蜂蜜是 2000~10000 mPa·s，
与这里的 XSPH 黏性系数**不是一个量纲**，不能直接换算。这里的比值（蜂蜜约为水的 40 倍）只是"观感上像那么回事"的量级。

#### 6 个笔刷工具（`#fluid-tools`）

| 工具 | 做什么 | 节流间隔 |
| --- | --- | --- |
| 💧 泼水 | 在笔刷中心生成一"泼"粒子，带初始向上速度（有抛物线） | 80 ms |
| 🚰 抽水 | 把笔刷范围内的粒子整体抽掉 | 40 ms |
| 🌊 加水 | 稳定地往里加粒子（比"泼"温和） | 60 ms |
| 🕳 减水 | 按比例减少粒子 | 40 ms |
| 🧊 冻结 | 把这块区域标成**冻结区**（里面的粒子每帧速度写 0） | 200 ms |
| 🔥 解冻 | 解除冻结区 | 200 ms |

**冻结区是按坐标判断的**（不是按粒子下标 —— 下标会变、坐标不会）。做闸门、做瀑布造型都靠它。

**用法**：按 `4` → 在面板里选类型与工具 → 在视口里**按住左键**（不用点一下，按住就持续作用）。
半径用 `#fluid-radius`（0.5~12 米），"一次倒多少"用 `#fluid-amount`（20~2000 个/次）。

#### 三种渲染风格（`#fluid-styles`）

| 风格 | 效果 |
| --- | --- |
| 粒子 | 每个粒子画一个小球/方盒（一条 `InstancedMesh`，手机端默认用方盒，12 个三角形省得多） |
| 表面 | 把粒子密度场重建出**连续液面** |
| 混合 | 表面 + 少量粒子点缀（表面重建分辨率之外的水花） |

#### 音效

勾「流体音效」`#fluid-audio-toggle` + 拖音量 `#fluid-volume`。
⚠ **必须点过一次页面才出声**（浏览器要求用户手势之后才能出声），面板上写着"等待一次点击"。
音效是 **Web Audio 现场合成**的，零音频素材。

#### 面板读数

粒子数 / 上限（`#fluid-count` / `#fluid-capacity`）、模拟耗时（`#fluid-sim-ms`）、
密度误差（`#fluid-density`）、平均邻居数（`#fluid-neighbors`）、质量档（`#fluid-quality`，
显示 LOD 0/1 与是否在慢动作）、表面重建状态（`#fluid-surface-note`）。
「清空全部流体」`#fluid-clear` 一键清掉所有粒子。

**怎么读"密度误差"**：它是 PBF 的密度约束残差。误差很小说明水是"实心"的；
如果你看到水在膨胀、并且"位置修正被上限夹住"的粒子数很多，那是水在炸的前兆 ——
代码里有一条断言专门盯着这个数。

### 11.2 沙土（`#sand-panel`，按 `5` 切到沙土工具）

沙**不是**一种普通体素，而是**有状态的格子**：每格记**湿度**与**稳定性**。

#### 湿度决定安息角

| 状态 | 湿度 | 安息角 | 滑动水平行程 | 实测堆出来的坡度 |
| --- | --- | --- | --- | --- |
| 干沙 | 0 | 34° | 1.48 格 | 31.6° |
| 湿沙 | 0.5 | 45° | 1.00 格 | 45° |
| 饱和沙 | 1 | 15° | 3.73 格 | 11.3° |

（实测值与目标值差 2~4°，这是离散格子的固有误差。**它是两档之间的概率混合，不是连续的角度控制**。）

#### 5 个工具（`#sand-tools`）

| 工具 | 效果 | 备注 |
| --- | --- | --- |
| ⛰ 堆沙 | 按 `cos(π/2·d/r)` 衰减堆出**沙丘**（不是圆锥） | 高度用 `#sand-height` 调（1~16 格） |
| ⛏ 挖沙 | 挖掉沙格 | |
| 💧 湿沙 | 提高湿度（能立得更陡） | |
| ☀️ 干沙 | 降低湿度 | |
| 🪨 凝固 | **把沙变成石头** | 不可逆，所以节流最长（300 ms），不该被误触连点 |

半径用 `#sand-radius`（1~12 格）。凝固后的石头会**从活跃集里摘掉**（石头不会被沙崩搬走）。

#### 沙崩与可视化

- **连锁**：一格动 → 唤醒邻居 → 邻居继续滑。一步搬动 **≥12 格**记为一次"沙崩事件"。
- 勾「显示沙崩可视化（角度 / 滑落方向 / 连锁范围）」`#sand-visual-toggle`：
  颜色按**稳定性**着色（不是只看湿度 —— 只看湿度的话，一堆压得很沉的干沙会被画成"很稳"），
  每个活跃格画一条"最陡方向"线，最近一次沙崩画一个范围框。所有线段合并成一条 `LineSegments`（1 次 draw call）。
- 面板读数：沙格数、干/湿/饱和各多少（`#sand-dry` / `#sand-wet` / `#sand-saturated`）、
  平均湿度（`#sand-moisture`）、一步耗时（`#sand-step-ms`）、活跃格（`#sand-active`）。
- 点「让全部沙重新检查稳定性」`#sand-mark-all` 会把所有沙格标记为活跃（大地形改过之后用）。

#### 沙水交互（自动发生，不需要设置）

| 现象 | 触发条件 |
| --- | --- |
| 变湿 | 流体盖住沙（占比 > 0.25），吸水速率 ∝ 流体占比 × dt |
| 侵蚀（泥流） | 流速 > 1.6 m/s **且** 沙的湿度 > 0.55（概率化） |
| 沉积 | 流速 < 0.35 m/s **且** 水里还有粒子 **且** 下方是固体 |
| 压塌 | 建筑顶上的沙格数 > 18（默认阈值）→ 把建筑转成动态刚体 |

### 11.3 存档与导出

- **保存到浏览器**：`Ctrl+S` 或点顶部「💾」。存在 localStorage，键名 `god-sandbox-save-v3`。
- **自动保存**：编辑停止 **4 秒**，或距上次保存 **30 秒**。可以在「📊 性能与调试」面板的
  `自动保存` 开关里关掉。
- **导出 / 导入 JSON**：点「⬇ 导出」`Ctrl+E` 的按钮，或「⬆ 导入」（快捷键 `Ctrl+O` 会打开文件选择框）。
  导出文件名形如 `god-sandbox-{seed}-{时间戳}.json`。
- **存档里有什么**（v3 格式）：`version / seed / mapId / worldSize / 尺寸 / simTime / camera / settings / chunks / buildings / groups`。
  - **水量也存**（否则"填满容器"就白做了）。
  - **RLE 压缩**：地下大片同种方块与天上的空气压得非常狠。
  - **v1 / v2 兼容读取**：老的 `god-sandbox-save-v2` 键仍能读（缺的水与建筑按空处理，尺寸回退到标准档）。
  - **载入尺寸不同的存档会自动重建世界**（按存档里记录的尺寸）。
- **流体与沙的存档**单独一条路径（`FluidSave`，格式 v1，魔数是 `GSFL`）：
  位置量化到 **1/512 米（约 2 毫米）**、速度量化到 **1/64 米/秒**、沙的湿度量化到 **1/255**，
  然后字节打包 + base64。**实测压缩率 50%**（24 字节/粒子 → 12 字节/粒子）。
  ⚠ 它是**有损压缩**：读回来之后流体的微观状态会变（粒子不会精确回到原来的位置），但宏观状态一致
  （同样的水面高度、同样的流向）。**粒子数精确相等** —— 少一个多一个都是 bug。

### 11.4 ⚠ 存档不含关节 / 触发器 / 逻辑连线

存档存的是建筑**实例 id**，而关节两端在 Rapier 里是**刚体 handle**，读档时刚体会全部重建、handle 全变，
所以需要先做"id ↔ handle"双向映射与重连。**这个还没做**。

**但绝不静默丢数据**：保存时如果世界里有关节/触发器/连线，会**明确弹出提示**告诉你读档后要重新摆。
所以：**接好关节的作品请用「导出蓝图」保存结构**，或者干脆别关页面。

| 综合测试 | 6000 粒子 + 200 箱 + 20 门 + 10 桥 + 1 船 | |

⚠ **加载压力场景会清空当前世界**（几百个刚体没法叠加到现有世界上）—— 走的是和换地图**同一条卸载路径**。
按钮上会写明将生成多少个物体，**手机端会降级**（粒子 ≤3000，刚体动态上限 300），
而且降级是**在生成之前就决定**的，不是生成到一半发现超限。降级后**目标帧率也从 30 降到 15**。

**目标帧率的出处**：需求给的通过标准只有两个数 —— **桌面 30 FPS+、移动端 15 FPS+**。
10 个场景的 `targetFps` 一律是这两个数，没有按场景"感觉"分别定目标（那会变成给难的场景偷偷放水）。
"采样 0 帧一律判不通过" —— 没测不等于通过。

### 12.2 怎么读那张报告表

点「生成报告（含对比）」`#btn-stress-report`，`#stress-summary` 与 `#stress-verdict` 会显示一行结论。它长这样：

```
10000 粒子水池｜桌面 像素比 1.00｜平均 30.0 / 最低 24.0 FPS（目标 30）→ 通过
｜中位 33.3 ms / p95 30.0 ms｜流体 1000 粒子 2.0 ms｜沙 0 格 0.5 ms｜
物理求解 3.0 ms｜流体耦合 1.0 ms｜渲染提交 8.0 ms｜刚体 10 / 接触对 50
｜堆 不可用｜显存 不可用
```

逐段读法：

1. **场景名 + 设备口径**：`桌面` / `移动端`，像素比。同一台机器改像素比后 FPS 不可比。
2. **平均 / 最低 FPS + 目标 + 结论**：结论是"通过 / 不通过"。**最低 FPS 比平均更值得看** —— 一秒钟掉到 12 FPS 的体验比稳定 28 更差。
3. **中位 / p95 帧时间**：p95 是"最慢的 5% 的帧有多慢"，它才是"卡顿感"的来源。
4. **各阶段耗时**：流体 / 沙 / 物理求解 / 流体耦合 / 渲染提交。
   - 需求给的预算：**物理单帧 5 ms**、**流体单帧 4 ms**。沙**没有**写死的验收线，所以只记录、不判定。
5. **刚体数 / 接触对数**：接触对是"求解器要解多少个接触"，它比刚体数更能解释物理耗时。
6. **堆 / 显存**：**拿不到就是「不可用」，绝不算成 0**。JS 堆只有 Chromium 内核能读（`performance.memory`），
   Firefox / Safari 拿不到；真实显存浏览器根本不暴露。显示 0 会被读成"占用为 0"，那是错的。

点「导出 JSON 报告」`#btn-stress-export` 存成文件。两次运行之间，`compareRuns` 会逐项给差值 + 百分比 + 中文结论
（变快 / 变慢 / 基本一样，**带宽 3%** —— 同一场景同一机器连跑两次差 1~2% 是常态）。

### 12.3 负载热力图（`#perf-heatmap`）

⚠️ **它画的是"负载估计（加权物件数）"，不是每帧实际耗时**。原因在 README 里；
面板上三处都写着这句（canvas 左下角的角标还**画进了位图**，截图传播也带着）。
色标的副标题是「估计值，不是毫秒」。权重：流体/沙土/地形/其它 = 1（单位口径），刚体 = **4（估计值）**。

怎么用：往东边堆东西帧率掉了，看热力图哪一格最亮 → 那一片物件最密 → 搬走或删掉那一片。

- **FPS、帧耗时、draw call、三角形、物理耗时、GC 次数（近似）、JS 堆、显存粗估、几何/贴图、材质**。
- **帧时间分布**（最近 120 帧）：中位数 / P95 / P99 / 慢帧占比 + 柱状图（**红柱 = 这一档已超预算**）+ 最近帧折线。
- **慢帧记录**：`#memp-slow-total` 是总条数（**同一原因会合并计数**），`#memp-slow-list` 列出原因。
  「慢帧阈值」`#memp-threshold` 默认 16.7 ms，可以调。
- **瓶颈判断** `#memp-diagnosis`：一句中文结论。
- 「导出性能报告」`#memp-export` 导出 JSON，可以直接贴进 Issue。

> 性能面板的**阶段拆分**是刻意分开的：`物理求解 / 水沙模拟 / 区块重建 / 支撑面索引 / 视锥剔除 / UI 面板 / 交互拾取 / 渲染提交`。
> 以前"渲染"是**残差**（扣掉前两段的一切），于是区块重建、支撑面、UI 都被算进"渲染"，
> 面板会一本正经地报"渲染是瓶颈"，把人引到错误方向。现在**各段各自计时**，渲染才是残差。

## 14. 教学关卡

### 14.1 教学关卡（3 关，10 步）—— `#tutorial-panel`

按顶部的「🎓 教学」或 `J` 开始/退出。三关是 **门 / 小车 / 桥**：

1. **门**：从建筑面板拿一扇木门放进门框 → 给门加一个旋转关节（铰链）→ 推它。3 步。
2. **小车**：放一块木地板当车板 → 加两个轮子（旋转关节）→ 推着走。3 步。
3. **桥**：立两根石柱 → 铺桥面 → 加关节 → 放重物压一压。4 步。

流程：**选模板 → 点「预览」看近似地形 → 调滑杆 → 点「生成」**。

| 模板 | 地形类型 | 推荐用途 | 默认世界档 |
| --- | --- | --- | --- |
| 🌾 平原村庄 | 平原 | 新手首选：地面平整，放东西不容易悬空 | 新手 |
| ⛰️ 高山峡谷 | 山地 | 试承重与支撑：坡多、悬挑容易出问题 | 标准 |
| 🏜️ 沙漠戈壁 | 沙漠 | 看沙子物理：安息角、流动与堆积 | 标准 |
| 🏝️ 群岛海域 | 群岛 | 大量水面 | 标准 |
| ❄️ 雪原 | 雪原 | 建筑稀疏 | 标准 |
| 🌋 火山 | 火山 | 岩浆与地形 | 标准 |
| 🌲 深林 | 森林 | 树密度 1.8 | 标准 |
| 🏙️ 城市街区 | 城市 | 建筑密度 1.8 | 标准 |

可调参数（滑杆）：树密度、建筑密度、小物品密度、山地比例、水体比例、种子。
点「导出最近一次生成日志」`#btn-export-generation-log` 导出 JSON（含每个阶段的耗时与统计）。

**9 个阶段的顺序不可换**：高度图 → 水体填充 → 沙地生成 → 地表材质 → 自然物 → 建筑规划 → 建筑生成 → 小物品 → 冲突检测与修复。
（"树不会被土盖、建筑不重叠不悬空、小物品不堵门"都由最后一个阶段保证。）

**生成预览是降采样近似**：画布右下角标着"近似预览 · 非真实体素"。它能告诉你地形大体长什么样，
但**看不出**小物品与门洞的冲突、洞穴与悬垂处不准、不跑物理。
「生成回滚」只回滚**参数 + 种子**，不保留体素副本。

### 15.3 冲突可视化（`#btn-conflict-overlay`）

点一下把最近一次生成的冲突画成彩框：**红 = 重叠，黄 = 悬空，橙 = 越界，紫 = 被埋，蓝 = 挡门**。
框的边长是按严重度放大的**标记**，**不是**真实相交体积（相交尺寸只在日志文字里）。
标记上限默认 400 个，超出部分会如实报告而不是静默丢弃。

### 15.4 内容使用统计（`#content-stats-panel`）

俯视热力图：你这张图里各个位置用了多少种/多少个物品，用来发现"我一直在用同一批东西"。
它**每 400 ms 刷新一次**（早期它挂在每帧路径上，实测 1.02 ms/帧，已优化到均摊 0.026 ms/帧）。

### 15.5 换地图 / 换世界

换图的唯一入口是菜单里的载入（或生成模板），流程是：
**确认（只在真有未保存改动时弹窗）→ 淡出黑幕 → 卸载清单 → 建新世界 → 生成内容 → 重建物理
→ 标记全区块待重建 → 复位相机 → 刷新界面 → 采样对比 → 淡入**。

卸载清单逐条执行、逐条计时、逐条报告，**一条失败不中断后面的**（10 条，从"解除拾取状态"到"复位命中与计数"）。
「📊 性能与调试」面板的「换图记录」会显示最近 12 次的内存变化。

判断有没有泄漏的方法：**连续切同一张地图 5 次，「几何」这一列应当回到同一水平。**

## 16. 常见问题

**Q1. 打开 `http://localhost:5173/` 是 404。**
地址要带仓库名：<http://localhost:5173/gad-box/>。这是 `base` 配置的预期行为。

**Q2. 我按下左键没有反应 / 没有笔刷光标。**
先确认工具对不对（顶部工具栏高亮的是哪个）：笔刷光标只在地形/流体/沙土工具下显示。
再确认是不是在双指手势中（手机上双指期间会暂停绘制）。

**Q3. 放东西时提示"不可放"，但那里明明是空的。**
可能是：① 目标位置和已有物体重叠（并列重叠查询）；② 地形穿插；
③ 悬浮而"放在空中会下坠"关掉了；④ 屋顶/天花板净空不够。按 `Tab` 换一个候选点看看。

**Q4. 我的东西浮在空中不掉。**
「🧪 物理沙盘模式」里的「全部转成动态刚体」没开的话，静态物体不会自己掉。
另外失去支撑的判定有 **600 毫秒宽限期**；还有「物理规则」里的「支撑检查」开关如果关着，就不会触发掉落。

**Q5. 水摊得很薄 / 一格水铺满一个大盆。**
元胞自动机的正常表现，不是 bug（没有最小厚度、没有压力与表面张力）。

**Q6. 湿度调了，干沙和饱和沙的坡度看起来还是差不多。**
安息角是**两档之间的概率混合**，不是连续角度控制。实测 31.6° / 45° / 11.3°。

**Q7. 我明明放的是 1000 个箱子，为什么只有 800 个？**
桌面动态刚体上限 800（移动端 300），超出的部分**退化成静态并记账**，摘要里显示"请求 1000 → 800"。

**Q8. 洪水场景冲不倒建筑。**
20000 粒子上限 = 81.9 m³ 水；把 20×20 街区淹到 0.5 米要 ≈48828 个粒子。所以只能做"街道浅水"。

**Q9. 性能面板说"渲染"是瓶颈，我先优化渲染吗？**
先看阶段拆分那一行。现在各段各自计时，渲染才是残差。看"最慢阶段"的中文标签更靠谱。

**Q10. 载入存档之后我接的关节都不见了。**
见 §11.4。存档不含关节/触发器/连线，保存时会有提示。接好关节的作品请用蓝图导出。

**Q11. 手机上很卡。**
点性能面板的「性能优先」；关掉「地形线框」与「区块边界」；确认世界档是新手（48×16×48 / 9 区块）；
关掉流体音效与表面渲染（切回「粒子」风格）。

**Q12. 我按了"回收内存"但内存没降。**
在没有 `window.gc` 的浏览器上它**做不到**真正回收 —— 面板会如实告诉你这句话，不假装成功。

**Q13. 沙崩可视化打开了但看不到东西。**
可视化只画**活跃格**。平铺静止的沙层活跃集是空的（搬动数为 0），所以什么都看不到 ——
点「让全部沙重新检查稳定性」把它们标记一遍，或者堆一个新沙堆出来。

**Q14. 快捷键速查表里写的键按下去没反应。**
见 §13 里标 ⚠ 的三处（`Tab`、`R`、`Ctrl+E`）：面板上那几行还没跟着引擎改。以本文档为准。
